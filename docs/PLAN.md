# «Ветераны» — план реализации v1

Документ фиксирует объём первой версии, архитектуру, схему данных и пошаговый
чеклист работ. Отметка `[x]` — выполнено, `[ ]` — предстоит.

- **Платформа:** Windows 10 x64 (Linux — задел на будущее, не входит в v1)
- **Пользователь:** один, локальная база
- **Стек:** C++17, Qt 6.5 LTS Widgets (LGPL, динамическая линковка), SQLite,
  QXlsx (MIT), QtPrintSupport
- **Поставка:** portable-папка (`windeployqt`) + инсталлятор Inno Setup
- **Связанные документы:** `docs/PRINT-LAYOUT.md` (макеты печати)

```
    └── import/   # IImportService + заглушка (v2)
```

Ключевые решения:

- **Модель:** `QAbstractTableModel` + `QSortFilterProxyModel` (сортировка) +
  цепочка второго прокси для быстрого поиска; данные грузятся в память целиком
  (до ~50 тыс. записей это мгновенно, дальше — SQL-пагинация, v2).
- **Настройки:** `QSettings` в формате INI рядом с exe (`settings.ini`) — portable.
- **Пути:** `data/veterans.db`, `backups/`, `logs/` рядом с exe; если каталог
  только для чтения (Program Files) — `%LOCALAPPDATA%\Veterans\`.
- **Печать и PDF** — один и тот же HTML-шаблон через `QTextDocument`, чтобы
  экранная карточка, PDF и принтер не расходились.
- **Никаких сетевых вызовов**, всё офлайн.

## 3. Схема базы (SQLite)

```sql
PRAGMA user_version = 1;

CREATE TABLE category (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE,
    sort_order INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE subscription (
    id         INTEGER PRIMARY KEY,
    name       TEXT NOT NULL UNIQUE,
    sort_order INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE person (
    id                INTEGER PRIMARY KEY AUTOINCREMENT,
    last_name         TEXT    NOT NULL,
    first_name        TEXT    NOT NULL,
    middle_name       TEXT    NOT NULL DEFAULT '',
    birth_date        TEXT    NOT NULL,           -- 'YYYY-MM-DD'
    microdistrict     INTEGER NOT NULL,           -- 1..999
    street            TEXT    NOT NULL DEFAULT '',
    house             TEXT    NOT NULL DEFAULT '',
    building          TEXT    NOT NULL DEFAULT '',
    apartment         TEXT    NOT NULL DEFAULT '',
    phone_type        INTEGER NOT NULL DEFAULT 0, -- 0 — домашний, 1 — мобильный (миграция 3)
    phone             TEXT    NOT NULL DEFAULT '',-- цифры: 5 или 11 на 7 (миграция 3)
    category_id       INTEGER REFERENCES category(id),
    visit_month       INTEGER,                    -- 1..12
    visit_year        INTEGER,                    -- 1990..2100
    subscription_id   INTEGER REFERENCES subscription(id),
    subscription_year INTEGER,
    created_at        TEXT    NOT NULL,
    updated_at        TEXT    NOT NULL,
    deleted_at        TEXT                        -- резерв под корзину (v2)
);

CREATE INDEX idx_person_name     ON person(last_name, first_name);
CREATE INDEX idx_person_birth    ON person(birth_date);
CREATE INDEX idx_person_micro    ON person(microdistrict);
CREATE INDEX idx_person_visit    ON person(visit_year);
CREATE INDEX idx_person_category ON person(category_id);
CREATE INDEX idx_person_sub      ON person(subscription_id);
```

Справочники (сид): категории — ветеран труда; инвалид; участник боевых действий;
участник СВО; член семьи СВО; ликвидатор ЧАЭС; несовершеннолетний узник; дети
войны; без льгот. Подписки — Железногорские новости; Ветеран.

## 4. Правила валидации

| Поле | Правило |
|---|---|
| Фамилия, имя | обязательны, 1–100 символов, буквы/дефис/пробел/апостроф |
| Отчество | необязательно, 0–100 |
| Дата рождения | обязательна, 01.01.1900 … сегодня, показывается `дд.мм.гггг` |
| Микрорайон | обязателен, целое 1–999 (не более 3 цифр) |
| Улица | 0–120 символов |
| Дом / корпус / квартира | 0–10 символов, буквы и цифры |
| Телефон | необязателен; домашний — ровно 5 цифр (на экране `X-XX-XX`), мобильный — 11 цифр на `7` (на экране `+7XXXXXXXXXX`). В базе хранятся только цифры, разделители добавляются при показе |
| Льготная категория | «без льгот» по умолчанию, значение только из справочника |
| Месяц/год посещения | месяц 1–12, год 1990 … текущий+1; пара заполняется целиком или пуста |
| Подписка | газета из справочника; если выбрана — год обязателен (2000 … текущий+1) |

## 5. Экранные формы

1. **Главное окно** — таблица + панель инструментов + быстрый поиск + счётчик.
2. **Карточка записи** (`PersonDialog`) — три режима: создание, просмотр, правка.
   Порядок верхней строки: **ФИО → дата рождения → телефон → радиокнопки
   «Домашний/Мобильный»** (дата рождения левее телефона).
3. **Расширенный поиск** (`SearchDialog`) — модальный.
4. **Настройки** (`SettingsDialog`) — модальный.
5. Системные: подтверждение удаления, «О программе», выбор файла БД, ошибки.

## 7. Критерии приёмки v1

1. На чистой Windows 10 приложение запускается из portable-папки без установки
   чего-либо ещё.
2. Создание, правка, удаление, сортировка по 7 столбцам, быстрый и расширенный
   поиск работают согласно ТЗ.
3. «Печать» неактивна без отмеченных строк; отмеченные строки подсвечены.
4. Печать списка и печать карточек по одной дают макеты из `PRINT-LAYOUT.md`,
   принтер выбирается в диалоге, есть предпросмотр.
5. Excel-файл открывается без предупреждений и сохраняет оформление.
6. Файл БД можно скопировать на другой ПК и продолжить работу.
7. Автобэкап создаётся раз в сутки, восстанавливается через настройки.
8. Интерфейс — светлые темы, читаемый текст при многочасовой работе.

## 9. Регламент работы с чеклистом

- За один заход выполняется **один пункт** чеклиста.
- Пункт помечается `[x]` только после фактического выполнения и проверки;
  если проверка невозможна в текущем окружении, это явно указывается.
- **После каждого выполненного пункта — саммари заказчику:** что сделано, где
  лежит результат, что проверено и что осталось (номера следующих пунктов).
- Первым всегда берётся ближайший невыполненный пункт; если он требует решения
  заказчика или внешнего окружения, берётся следующий выполнимый, а пропущенный
  помечается как «ожидает заказчика».
