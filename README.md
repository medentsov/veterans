# Ветераны

Настольное приложение для учёта ветеранов: справочник записей, отметки,
быстрый и расширенный поиск, экспорт в Excel и PDF, печать списков и карточек.

- Язык: C++17, Qt 6.5 (Widgets, Sql, PrintSupport), QXlsx (MIT).
- Платформа поставки: Windows 10/11 x64.
- Версия: 0.1.0.

## Требования

- Qt 6.5 LTS или новее (компоненты Core, Gui, Widgets, Sql, PrintSupport).
- CMake 3.21+.
- Windows: MinGW 11.2 x64 или совместимый тулчейн.

## Сборка

```bash
cmake --preset release
cmake --build --preset release
```

На Windows то же самое одной командой — `build.ps1`: он настраивает и собирает
пресет `release`, затем копирует библиотеки Qt рядом с exe через `windeployqt`
(нужен Qt в `PATH` или параметр `-QtBin`). Ключи: `-Tests` — собрать и прогнать
автотесты, `-NoDeploy` — собрать без windeployqt.

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1
```

Готовый `Veterans.exe` появляется в `build/release/`. Для запуска рядом должны
лежать DLL Qt и плагины — при упаковке их копирует `windeployqt`.

## Запуск

Приложение не требует установки и работает в portable-режиме: если каталог с
`Veterans.exe` доступен для записи (флешка, «Рабочий стол», распакованный
архив), все данные лежат рядом с программой. Если каталог только для чтения
(например, `Program Files`), данные уходят в профиль пользователя, чтобы
приложение работало без прав администратора.

## Расположение данных

| Что | Где |
| --- | --- |
| База данных | `data/veterans.db` (или файл, выбранный в настройках) |
| Журналы | `logs/` |
| Резервные копии | `backups/` |
| Настройки | `settings.ini` |

В профиле пользователя: `%LOCALAPPDATA%\Veterans` (Windows) или
`~/.local/share/Veterans` (Linux).

Файл базы можно сменить в «Настройках» → «База данных» → «Сменить файл…».
Изменение применяется после перезапуска; прежняя база остаётся на диске.

## Резервное копирование

- При запуске создаётся суточная копия — не чаще одного раза в день.
- Хранится до 10 последних копий, старые удаляются автоматически.
- Вручную: «Настройки» → «Резервные копии» → «Создать копию сейчас».
- Восстановление: «Настройки» → «Резервные копии» → выбрать копию в списке →
  «Восстановить…». Текущая база перед заменой сохраняется как
  `veterans-before-restore-*.db`, приложение перезапускается автоматически.
- Копия снимается через `VACUUM INTO`, поэтому её можно делать при открытой
  базе: SQLite сам собирает согласованный снимок с учётом журнала WAL.

Для переноса на другой компьютер скопируйте `data/veterans.db` (или выбранный
файл) вместе с программой. Перед заменой базы закройте приложение.

## Экспорт и печать

- «Файл» → «Экспорт в Excel»: отмеченные записи, все или результат фильтра.
- «Файл» → «Экспорт в PDF»: список на A4 в альбомной ориентации.
- «Печать»: «Записи в списке» и «Каждую отдельно» (карточки).
- Печать доступна только при отмеченных записях; предпросмотр открывает
  штатный диалог выбора принтера и копий.

## Типовые проблемы

| Симптом | Что делать |
| --- | --- |
| «Не удалось открыть базу данных» | Проверьте права на каталог и свободное место; подробности — в `logs/`. |
| «Файл занят» при экспорте | Закройте файл в Excel или просмотрщике и повторите. |
| Нет кириллицы в PDF | Установите шрифт с кириллицей (например, Noto Sans) или выберите системный шрифт. |
| Неверный масштаб интерфейса | Проверьте масштаб DPI в настройках Windows (125–200 %). |
| Печать недоступна | Отметьте записи галочками — без них печать отключена. |
| Настройки не сохраняются | Убедитесь, что каталог программы доступен для записи, либо запускайте из папки на диске. |
| `windeployqt`: «Unable to find the platform plugin» | Не передавайте `--release` для MinGW: debug/release определяется по флагу PE, которого GNU ld не ставит. `build.ps1` использует автоопределение — запускайте его, а не `windeployqt` вручную. |
| Автотесты не печатают «Проверок: …» | Qt пишет в stderr, только когда видит консоль, иначе сообщения уходят в `OutputDebugString`. `build.ps1` выставляет `QT_ASSUME_STDERR_HAS_CONSOLE=1`; при ручном запуске задайте эту переменную сами. |

## Linux и AppImage

Код не использует WinAPI и собирается кроссплатформенно средствами Qt:
`windows.h`, `WinMain`, `HWND` и другие платформенные вызовы в исходниках
отсутствуют (это проверяет `tools/check_docs.py`). Сборка под Linux возможна,
но официальная поставка проекта — Windows. AppImage в текущую версию не
входит: при необходимости пакет можно собрать отдельно из тех же исходников
и Qt 6.5.

## Проверки без Qt

Скрипты `tools/check_*.py` проверяют схему БД, репозиторий, экспорт, печать,
настройки, заглушки и документацию без сборки Qt:

```bash
for f in tools/check_*.py; do python3 "$f" || exit 1; done
```

Кириллица в готовых PDF и Excel проверяется по документам автотестов
(нужна сборка с `-DVETERANS_BUILD_TESTS=ON`):

```bash
cmake -S . -B build -DVETERANS_BUILD_TESTS=ON
cmake --build build --target veterans_tests
VETERANS_TEST_OUT=build/test-out ./build/tests/veterans_tests
python3 tools/check_pdf_text.py build/test-out
```

Без сформированных документов `check_pdf_text.py` пропускает проверку.

## Проверка на реальной сборке

Полный цикл «сборка → автотесты → документы» проверен на Qt 6.12 (Linux,
платформа `offscreen`, M12-09):

```bash
cmake -S . -B build -DVETERANS_BUILD_TESTS=ON -DCMAKE_BUILD_TYPE=Release
cmake --build build
QT_QPA_PLATFORM=offscreen VETERANS_TEST_OUT=build/test-out ./build/tests/veterans_tests
python3 tools/check_pdf_text.py build/test-out
```

Результат: автотесты 97/97, проверки PDF/Excel 9/9. Приложение, запущенное из
пустой папки, создаёт `data/veterans.db` (схема v3), `logs/app.log` и суточную
копию в `backups/`.

Тот же цикл проверен на целевой платформе — Windows 10 Pro 22H2, Qt 6.5.3,
MinGW 11.2.0, CMake 4.5.1 (M1-07):

```powershell
powershell -ExecutionPolicy Bypass -File build.ps1 -Tests
```

Результат: `Veterans.exe` и `veterans_tests.exe` собраны, DLL и плагины Qt
разложены рядом (`platforms\`, `styles\`, `sqldrivers\`), автотесты — «Проверок:
97, провалов: 0». Запуск с PATH без Qt и MinGW создаёт `data/veterans.db`
(WAL), `logs/app.log`, `settings.ini` и суточную копию в `backups/`.

Сформированные документы можно проверить отдельно:

```bash
python3 tools/check_pdf_text.py build/test-out
python3 tools/check_excel_export.py build/test-out/list.xlsx
```

## Проверка на Windows

Пошаговый чеклист для целевой машины (установка Qt, сборка, portable-архив,
принтер, Excel/PDF, приёмка) — `docs/WINDOWS-CHECKLIST.md`.

Визуальная сверка макетов печати (M0-08) выполняется без Windows:

```bash
pdftoppm -r 110 -png build/test-out/card.pdf card
pdftoppm -r 110 -png build/test-out/list.pdf list
```

Полученные PNG сравниваются с `docs/PRINT-LAYOUT.md`.
